# Участок медного карьера (команда)

Двойники и симулятор для Концепции из [SUBMISSION.md](../../SUBMISSION.md). Полная схема, список двойников и источники цифр — в [team/docs/design-twins.md](../docs/design-twins.md); здесь только то, что нужно, чтобы запустить и проверить.

```text
Забой-1 (выше Cu) ──[Экскаватор-01]──┐
                                       │ road-face1
                                       ▼
                                Развязка (junction-01) ──road-main-a (основная)──┐
                                       ▲                 ──road-main-b (резерв)──┤──▶ Дробилка CR-01 ──▶ Конвейер ──▶ фабрика (вне модели)
                                       │ road-face2                              │         │
Забой-2 (ниже Cu) ──[Экскаватор-02]──┘                                          ▼         ▼
                                                                            Рудный склад (буфер, если дробилка стоит)

Вскрышной уступ ──[Экскаватор-03]──road-waste──▶ Отвал вскрыши
```

Namespace Ditto: `org.openegiz.pit`. 29 двойников (14 типов), самосвалы — общий парк, диспетчер переназначает их между тремя экскаваторами через признак `assigned_excavator`.

## Запуск (dev-оверлей этого этапа)

```bash
make team-mine
```

Поднимает платформу (если не запущена) и наш оверлей поверх неё. Двойники — в Grafana → приложение **OpenEgiz** → **Twins**, под namespace `org.openegiz.pit`. `make team-mine-stop` останавливает симулятор, двойники и данные остаются. `make down` / `make up` дальше поднимают и опускают всё вместе, `make clean` забывает оверлей.

Эта же цель — и точка входа для Сборщика: корневой README.md просит выполнить именно `make team-mine`.

## 3D-сцена и панель сценариев

**http://localhost:8091** — Three.js-сцена участка (свой код, не Unity-панель платформы): стилизованный карьер на закатном солнце — террасированная чаша со съездным серпантином, забои с развалом горной массы, экскаваторы с анимированным циклом черпания, движущиеся самосвалы (кузов — по состоянию, стоп-сигналы при остановке, пыль из-под колёс у гружёных), дороги с барьером при закрытии, склад, дробилка, конвейер, отвал.

Над каждым объектом — подпись с его текущим показателем из Ditto (содержание Cu, т/ч, тоннаж смены, заполнение склада, состояние дороги), так что основное читается без кликов. Клик по объекту (в том числе по дороге) подсвечивает его кольцом и открывает карточку двойника справа, которая дальше обновляется вживую. Четыре панели поверх сцены:

- **Сценарии «что если»** (внизу слева) — кнопки на все 4 события из Decision: отказ экскаватора-01/-02, закрытие основной/резервной дороги, остановка дробилки, вывод из строя двух самосвалов (нехватка). У каждого — кнопка отмены. Пока сценарий активен, строка подсвечивается красным с меткой «активен», а кнопка, которая ничего не сделала бы (закрыть уже закрытую дорогу), блокируется; под кнопками видно «было → сейчас» по пропускной способности и проценту плана. Активность определяется чтением атрибутов двойников, а не локальным флагом, поэтому после перезагрузки страницы панель по-прежнему показывает правду.
- **Диспетчеризация** (внизу, рядом) — выпадающий список у каждого самосвала, переназначает его на другой экскаватор (пишет `attributes.assigned_excavator`). Это и есть модуль «диспетчеризация».
- **Контроль качества руды** (внизу справа) — модуль, сравнивающий текущее содержание в подаче (`shift-01.grade_actual`) с минимумом плана и с содержанием по двум забоям, даёт текстовую рекомендацию (на какой забой сместить самосвалы).
- **Автодиспетчер** (внизу справа, крайняя панель) — оптимизатор распределения парка. Перебирает все 28 раскладок шести машин по трём экскаваторам, для каждой считает подачу руды и среднее содержание по модели цикла погрузки-откатки, и показывает текущий расклад против оптимального плюс прямое указание, сколько машин куда перевести. **Только советует, в Ditto не пишет ничего** — применяется совет руками в панели «Диспетчеризация». Строка «Цикл» показывает время рейса по каждому экскаватору с пометкой «расчёт» или «факт»: после трёх завершённых рейсов модуль переходит с теоретического времени на замеренное по телеметрии. Подробнее о методе и о том, почему не обучали модель, — design-twins.md §9.

KPI-строка вверху оценивает, а не просто показывает: выполнение плана сравнивается с тем, сколько смены уже прошло, содержание — с минимумом плана, т/ч — с паспортным диапазоном дробилки. Отклонение не только окрашивается, но и помечается знаком (`!`, `✕`), чтобы читалось в оттенках серого и при дальтонизме. Кнопка **«Скрыть панели»** внизу или клавиша **H** убирают панели, оставляя только KPI-строку — сцена видна целиком (удобно и для скриншотов).

### Как это работает технически

Страница — статика (`viewer/public/`), отдаётся своим nginx. Авторизация к Ditto не попадает в браузер: nginx в контейнере вьюера сам добавляет `Authorization: Basic …` (из `DITTO_PASSWORD`, см. `viewer/entrypoint.sh`) ко всем запросам на `/ditto/*`, проксируя на `ditto-nginx`. Это не только безопаснее, но и единственный способ завести Server-Sent Events вообще: у браузерного `EventSource` нет способа самому выставить заголовок `Authorization`, а Ditto как раз и отдаёт live-обновления через SSE на `/api/2/things` (`Accept: text/event-stream`, см. [httpapi-sse](https://eclipse.dev/ditto/httpapi-sse.html)). Запись команды — `PUT .../attributes/<имя>` (не в признак: почему именно так — разделом выше).

Three.js (r169) и используемые addon-модули из его же `examples/jsm` — OrbitControls, Sky и стек пост-обработки (EffectComposer + UnrealBloomPass для свечения ламп и маяков) — не с CDN, а в репозитории (`viewer/public/vendor/`, список и лицензии в `vendor/NOTICE.md`), чтобы сцена открылась и без интернета на машине Сборщика — та же причина, по которой платформа вендорит Grafana-плагины.

Геометрия карьера на сцене — схематичная, подогнанная под граф дорог, а не настоящий рельеф: реальная геометрия Актогая не источник (см. Concept).

## Дашборд Grafana (дополнение к сцене)

Grafana → **Dashboards → Участок карьера → Участок медного карьера (team-025)**. Не замена 3D-сцене — сцена показывает текущий момент, дашборд показывает **историю по смене**, чего на сцене принципиально не видно: тренд подачи на дробилку и содержания (с линией плана), заполнение склада-буфера со временем, топливо по каждому самосвалу, таблицы состояния самосвалов/экскаваторов/дорог.

Код: [generate_dashboard.py](generate_dashboard.py) → `dashboard.json`, по образцу `examples/mine/dashboard.json`. Подключён через собственный provisioning-провайдер Grafana (`deploy/compose/grafana/provisioning/dashboards/openegiz.yaml`, провайдер `team`, папка «Участок карьера» — не смешан с папками платформы или примера) и volume в `compose.yml` (`grafana.volumes`).

**Важный технический нюанс**, из-за которого пришлось переписывать две из трёх таблиц: Flux-функция `pivot()` требует, чтобы столбец `_value`, из которого она строит колонки, был одного типа. Если смешать в одном запросе строковое поле (`state`) и числовые (`trips_total` и т.п.), Ditto/InfluxDB отработают нормально, а вот сам Flux-запрос упадёт с `schema collision detected: column "_value" is both of type string and float` — не ошибка данных, ошибка именно формы запроса. Решение — разделить строковые и числовые признаки на разные `targets` и смержить `joinByField` (ровно так уже сделано у `examples/mine/dashboard.json`, но я не сразу это заметил и один раз наступил на те же грабли). Все 13 панелей проверены напрямую через `influx query` (не только через Grafana) — см. git-историю.

## Как идут данные

```text
simulator.py (SimPy) ──MQTT telemetry/<twin>──▶ Ditto ──MQTT opentwins/#──▶ Telegraf ──▶ InfluxDB ──▶ Grafana
                       ◀──REST GET (опрос, тот же тик, прямо перед публикацией)── Ditto ◀── правки диспетчера (Grafana/Twins)
```

Симулятор публикует полный набор **признаков** (`features`) каждого двойника, как и Пример рудника. В отличие от Примера, он ещё и **опрашивает** Ditto: команды диспетчера читаются одним пакетным запросом каждые `--interval` секунд, прямо перед публикацией того же тика. Правка в Grafana/приложении Twins доходит до симулятора без перезапуска. Почему опрос, а не подписка на поток событий Ditto — см. design-twins.md §5.

**Кто чем владеет.** Команды диспетчера живут в `attributes` и читаются симулятором только на чтение: `closed` у дороги, `forced_down` у экскаватора/самосвала/дробилки, `assigned_excavator` у самосвала. Вся телеметрия, включая `state`, живёт в `features`, и её пишет только симулятор.

Разделение обязательное, а не косметическое: публикация — это `modify` на `/features`, которая заменяет **все** признаки двойника разом, поэтому команда, лежавшая в признаке, могла быть затёрта публикацией, собранной за мгновение до того, как команда дошла; дальше опрос читал обратно собственное устаревшее эхо, и команда пропадала молча (ловилось примерно в одной попытке из четырёх, см. design-twins.md §7). До `attributes` публикация признаков не дотягивается, поэтому потеряться команда уже не может — худший случай теперь «сработает на тик позже».

У самосвала `assigned_excavator` есть и в `attributes`, и в `features`, и это разные вещи: в атрибуте — приказ диспетчера, в признаке — экскаватор, на который самосвал фактически работает (приказ вступает в силу, когда самосвал доезжает до ближайшей безопасной точки цикла). У дороги так же: `attributes.closed` — команда, `features.state` — зеркало, которое ведёт симулятор и читают сцена, Grafana и InfluxDB.

## Проверка

1. `make team-mine`, подождать, пока три сервиса (`team-mine-setup`, `team-mine-simulator`, `team-mine-viewer`) поднимутся: `make ps`.
2. Twins created: `make tail S=team-mine-setup` — должно быть `29 twins ready`.
3. Телеметрия идёт: `make tail S=team-mine-simulator` — раз в ~15 публикаций строка `sim NNN min | crusher ...`.
4. В Ditto: `curl -u ditto:$DITTO_PASSWORD http://localhost:8080/api/2/things/org.openegiz.pit:crusher-01` — `throughput_tph` должен расти от 0 и выйти на ~2850 т/ч за первый час симулированного времени.
5. В Grafana: Explore → InfluxDB → `mqtt_consumer` с тегом `thingId=org.openegiz.pit:crusher-01` — видны точки с полем `value_throughput_tph_properties_value`.
6. Откройте **http://localhost:8091** — сцена должна загрузиться, самосвалы — двигаться по дорогам, KPI-строка вверху — обновляться. Откройте консоль браузера — не должно быть ошибок `fetch`/`EventSource` (если есть — почти наверняка дело в `/ditto/` проксировании, см. `viewer/nginx.conf.template`).
7. Сценарий «что если», через UI вьюера (кнопка в панели) или напрямую в приложении Twins: `org.openegiz.pit:road-main-a` → `attributes.closed=true`. Поперёк дороги на сцене встаёт барьер, самосвалы на руде должны пойти через `road-main-b` (видно по изменившемуся пути) в течение `--interval` (по умолчанию 2 c); если закрыть и `road-main-b` — встать в `blocked_at_junction`. Обратная команда (или кнопка отмены) — `attributes.closed=false`.
8. Смены сменяются: оставьте стенд работать — через 12 ч симулированного времени (при ускорении 10× это ~72 реальных минуты) счётчики смены обнулятся, а `shift-01.shift_number` станет `2`. В KPI-строке вьюера это видно как «минут до конца смены №2».

**Живьём проверено** (`make team-mine` на реальной машине): шаги 1–5 целиком — 26 твинов создаются, симулятор публикует, throughput_tph доходит до ~2850 т/ч и лежит в InfluxDB под правильными именами полей (`value_<feature>_properties_value`) для всех 26 твинов. Вьюер проверен через curl (без браузера, см. ниже) — статика отдаётся, `/ditto/` проксирует REST и SSE без единого запроса пароля от браузера (nginx сам подставляет `Authorization`), формат SSE-событий совпадает с тем, что разбирает `app.js`. Сценарии «что если» проверены и через Ditto REST API, и нажатием самих кнопок в браузере: закрытие `road-main-a` срабатывает 8 раз из 8 (раньше терялось примерно раз из четырёх), экскаватор и дробилка уходят в `down` и поднимаются обратно обратной командой за несколько секунд. Перекат смены проверен прогоном симулятора на большом ускорении: смена №1 заканчивается на ~91% плана, смена №2 стартует с нуля.

**Рендер WebGL проверен в настоящем браузере** — Chrome headless с программным растеризатором (реальный WebGL-контекст и реальный Three.js, но без GPU): сцена собирается без ошибок консоли, подписи показывают живые значения, клик по объекту даёт подсветку и карточку двойника, закрытая дорога получает барьер. **Не проверено**: поведение на реальной видеокарте и частота кадров на слабой машине. Откройте **http://localhost:8091** сами и свяжитесь, если что-то не так (скорее всего в `app.js`, логика позиционирования расписана в design-twins.md §6).

Платформа была остановлена между сессиями (не `make down` намеренно, а просто простой) — после `make team-mine` на чистом старте должно повториться то же самое; если нет, первым делом `make logs S=team-mine-simulator` и `docker compose ... logs telegraf`.

## Что сознательно упрощено

- Опрос Ditto вместо подписки на поток событий (design-twins.md §5) — на несколько секунд медленнее реагирует на ручную правку, зато сильно проще и надёжнее.
- `repair-zone` (ремзона) считает, сколько единиц сейчас в `state=down`, но технику туда физически не возит — экскаватор чинят на месте, самосвал просто выбывает.
- `fuel-station` обслуживает самосвал там, где он есть (мобильный топливозаправщик), а не наоборот — самосвал никуда к ней не едет.
- Расход топлива списывается одним куском в конце плеча, не плавно по ходу движения.
- MTBF/MTTR и надёжность — иллюстративные допущения (небиблиографический источник), не выдаются за точные данные; см. design-twins.md §3.5.

## Переменные окружения симулятора

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MQTT_HOST` / `MQTT_PORT` | `localhost` / `1883` | брокер для публикации телеметрии |
| `DITTO_URL` / `DITTO_USER` / `DITTO_PASSWORD` | `http://localhost:8080` / `ditto` / — | опрос управляемых признаков |
| `SIM_INTERVAL` | `2` | реальных секунд между публикациями (и опросами Ditto — один таймер на оба) |
| `SIM_SPEEDUP` | `10` | симулированных секунд на реальную секунду |
| `SIM_SEED` | `42` | seed генератора случайных чисел |

`python simulator.py --dry-run` печатает сообщения в stdout вместо публикации и не обращается к Ditto — для локальной проверки логики без платформы.
